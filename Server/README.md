# LumaDesk Sync 2.1

Сервер аккаунтов и синхронизации для LumaDesk 2.1. Это готовый к установке
проект; публичный сервер, домен и учётные записи заранее не создавались.
Клиент Windows находится на уровень выше — `LumaDesk.exe`.

## VPS без домена, только IP

Для Ubuntu 22.04 без Nginx есть отдельная инструкция **README-IP.md**
и файлы `compose.ip.yaml`, `Caddyfile.ip`, `.env.ip.example`.
Они включают публичный HTTPS по IPv4 и не требуют домена.
Остальные варианты ниже предназначены для запуска с доменом.

## Что требуется

VPS с Linux, Docker Engine и Docker Compose; постоянный диск, домен или поддомен
с A-записью на VPS. Для первого варианта нужны свободные порты TCP 80 и 443.
Запись AAAA добавляйте только при работающем IPv6.
Docker: https://docs.docker.com/engine/install/
Если порты уже заняты Nginx, используйте второй вариант ниже.

## Вариант 1: отдельный сервер с автоматическим HTTPS

Загрузите всю папку `Server` на VPS. Из неё:

```bash
cp .env.example .env
nano .env
```

В `.env` замените `DOMAIN` на реальный поддомен без `https://`,
`ACME_EMAIL` — на свой адрес для сертификата. Не оставляйте значения `.example`.
Настройте DNS и разрешите входящие TCP 80/443 в сетевом экране сервера.
Затем:

```bash
docker compose up -d --build
docker compose logs --tail=60 caddy api
```

Проверьте `https://ВАШ-ДОМЕН/health`: ожидается
`{"status":"ok","version":"2.1"}`. В клиенте указывается `https://ВАШ-ДОМЕН`,
без `/health` и без `/v1`. Caddy получает и обновляет TLS-сертификат.
Не публикуйте порт контейнера API отдельно: наружу работает только Caddy.

## Вариант 2: VPS с существующим Nginx и HTTPS

Не запускайте основной compose-файл, чтобы не занимать чужие 80/443.
Из этой папки:

```bash
docker compose -f compose.existing-proxy.yaml up -d --build
```

API будет доступен на VPS только через `127.0.0.1:8765`.
Создайте HTTPS-виртуальный хост для своего поддомена с действительным
сертификатом и добавьте в него блок из `nginx-location.conf.example`.
В Nginx не доверяйте входящему `X-Forwarded-For`: пример заменяет его
реальным адресом подключения. Проверьте конфигурацию и перезагрузите Nginx.
Адрес в клиенте тот же: `https://ВАШ-ДОМЕН`.

## Аккаунт в Windows-клиенте

1. В трее LumaDesk выберите «Аккаунт и синхронизация».
2. Введите HTTPS-адрес установленного сервера.
3. Откройте «Регистрация»: логин 3–32 знака латиницей, пароль 12–128 знаков.
4. Выберите, добавлять ли существующие события этого ПК в аккаунт.
5. На втором компьютере выберите «Войти» и тот же сервер.

Это регистрация по логину, без проверки e-mail. Письма для восстановления
пароля не отправляются. В интерфейсе есть смена пароля; забытый пароль
сбрасывает администратор сервера (команда ниже).

Перед первым подключением клиент делает локальную копию настроек в
`%LOCALAPPDATA%\LumaDesk\backups\before-account-*.json`.
При входе галочка импорта по умолчанию выключена: данные другого аккаунта
на компьютере не отправляются автоматически. При регистрации она включена
и видна пользователю. При повторном входе в тот же аккаунт после истечения
сеанса незагруженные изменения объединяются с прежней базой синхронизации.

## Что синхронизируется

Заметки (название, полный текст, изменения и удаления);
будильники, напоминания, дата/местное время, повторения, включение событий,
интервал откладывания, выбор встроенной мелодии; общий звук, секунды,
прозрачность, прилипание, выбранный город и источник погоды.

Положение и видимость виджетов, закрепление, «поверх окон» и автозапуск
остаются отдельными на каждом ПК. Собственные WAV-файлы и их пути
не загружаются. На другом ПК для такого события используется «Рассвет»;
собственный файл можно выбрать отдельно на каждом устройстве.
Время событий — местное время Windows каждого компьютера, а не UTC.
Сигналы могут работать на нескольких компьютерах. Изменения срабатывания,
включения и откладывания также передаются при следующей синхронизации.

Автоматический обмен — раз в минуту, ручной — через трей или окно аккаунта.
Без сети программа работает локально; изменения отправляются после восстановления
связи. Сеанс действует 30 дней; затем нужно войти снова.
Выход выполняется на данном ПК, локальные события остаются. Если сервер
недоступен при выходе, локальный ключ удаляется, а серверный сеанс истечёт
по сроку или будет отозван при смене пароля.

## Конфликты и сохранность

Сервер принимает запись только на известной клиенту версии (CAS).
При параллельном изменении клиент объединяет независимые правки.
Удаление на одном ПК удаляет неизменённое событие на другом.
При редактировании одного события с двух ПК сохраняется вторая версия
с пометкой «копия конфликта». При споре удаления и редактирования
сохраняется отдельная копия отредактированного события.
При одновременном изменении одного общего параметра приоритет у локальной
правки синхронизирующегося клиента; настройка города и координаты объединяются
как одно целое. Перед первым подключением всегда создаётся резервная копия.
Лимит аккаунта — 1000 событий и 500 заметок; текст заметки до 20 000 знаков,
всех заметок — до 200 000 знаков. Документ — до 900 000 байт, запрос — до 1 МБ; превышение отвергается,
а не обрезается молча.

## Хранение и доступ

Пароли хешируются PBKDF2-HMAC-SHA256 с уникальной солью и 600 000 итераций.
Сервер хранит только SHA-256-хеши случайных ключей сеансов. Есть срок действия,
выход, лимиты попыток входа/регистрации и отзыв других сеансов при смене пароля.
Windows-клиент сохраняет ключ через DPAPI текущего пользователя,
в `%LOCALAPPDATA%\LumaDesk\account.json`. Пароль на диске не сохраняется.
HTTPS обязателен для удалённых адресов; HTTP разрешён только для loopback
при локальной разработке. Перенаправления с ключом сеанса не выполняются.

Данные событий лежат в SQLite в серверном томе `app_data`. Это НЕ сквозное
шифрование: администратор VPS может читать базу и резервные копии.
Не публикуйте базу, `.env`, резервные копии или токены в интернете.
У разных пользователей отдельные документы; идентификатор пользователя
определяется по сеансу, а не принимается из тела запроса.

## Резервные копии и обслуживание

Для основного варианта compose (для второго добавляйте `-f compose.existing-proxy.yaml`):

```bash
docker compose exec api python manage.py backup /data/backups/manual.sqlite3
docker compose cp api:/data/backups/manual.sqlite3 ./lumadesk-backup.sqlite3
```

Команда использует SQLite Backup API и корректна при работающем сервере.
Храните копии отдельно от VPS; настройте регулярное копирование у себя.
Не копируйте только основной `.sqlite3` из активной WAL-базы вручную.

Сброс забытого пароля — в терминале администратора, ввод скрыт:

```bash
docker compose exec api python manage.py reset-password USERNAME
```

Все сеансы этого аккаунта отзываются. События сохраняются.
Регистрацию после создания нужных аккаунтов можно закрыть:
в `.env` установите `LUMADESK_REGISTRATION=false`, затем
`docker compose up -d`. Для изменения кода: `docker compose up -d --build`.
Обычный `docker compose down` сохраняет данные. Команда `down -v` удаляет тома.

## Локальная разработка и тесты

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
LUMADESK_DB=./data/dev.sqlite3 uvicorn app:app --host 127.0.0.1 --port 8765
```

В Windows-клиенте для этого теста допустим адрес `http://127.0.0.1:8765`.
Не открывайте этот HTTP-порт в интернет. Для C#-проверок см. `../Tests/README.txt`.

Проверены API-регистрация, разделение пользователей, ошибки входа,
защита от параллельной записи, повтор запроса, отзыв/истечение сеансов,
смена пароля, валидация и лимиты. Также проведён прямой HTTP-тест
скомпилированного C#-клиента с работающим Python-сервером на loopback.
Окно аккаунта и DPAPI в настоящей Windows здесь не проверялись.
Публичный VPS, DNS и выпуск сертификата нужно проверить при развёртывании.

## Совместимость 2.1

Используйте клиент и сервер 2.1 из одного архива. Формат синхронизации — schema 2.
При первом запуске новая версия автоматически переносит документы schema 1:
добавляет пустой список заметок, сохраняет события, настройки, аккаунты и сеансы.
Записи старого клиента с schema 1 отвергаются, чтобы он не удалил заметки.
Перед обновлением существующего сервера сделайте резервную копию базы; при первой
установке перенос не нужен. Не удаляйте Docker volume при обновлении.
Правила конфликтов, автономной работы и импорта распространяются и на заметки.
